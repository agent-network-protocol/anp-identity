# Domain consent

The Host domain policy authorizes discovered public HTTPS reads by the default published identity. ANP signs only exact discovered GET/HEAD requests through a context-bound read facade. OpenAPI operations with extra scopes or malformed security requirements are not automatic reads. This permission does not expose generic signing, private keys, control-plane routes or account credentials.

Writes and extra permissions use `bindDomainOperationConsumer()` from the installed PAP or MCP domain adapter. `request()` records an exact normalized HTTP operation; `status()` waits for its owner decision; `cancel()` can only cancel requests owned by that facade, including during teardown. `execute()` admits a matching once grant and supplies an asynchronous assertion to check immediately before physical network send. The effect and post-effect checks retain unknown outcomes rather than claiming a rejected write never executed. The Host never clicks an approval or automatically refunds a consumed once grant.

`anp-domain/1` and `domain-operation/1` snapshots cannot create permanent grants. New requests carry `approvalProfile: exact-operation/1`; denials bind the exact operation fingerprint instead of disabling unrelated future operations. Retrying a denied operation is an explicit owner action and does not clear other operation denials. Legacy plugin-wide denials remain unchanged. All method, target, query, headers and body fields participate in the normalized operation binding.

The owner dialog shows a redacted bounded parameter preview and the SHA-256 of the actual request body. Preview data stays in bounded Host memory, not the durable authorization ledger. Missing previews cannot be approved or executed after restart. Background tabs do not consume the foreground approval prompt; deferring a batch does not disable future prompts. No full-write permission setting is included in this release.

MCP extra-scope discovery and the eventual business call are separate once confirmations. A temporary machine signer is restricted to the consented resource/scopes and live execution, then disposed. The matching MCP adapter also checks the physical tools/call name and canonical arguments before sending, never reuses an elevated session for another operation, and retains encrypted credential history while revocation may remain unconfirmed. PAP consent does not synthesize account OAuth credentials or widen an account token's scopes.

Before downgrading, cancel pending requests created by the new flow and revoke/archive grants using these snapshot profiles. Older readers reject the new grant snapshot, but old pending-request readers do not understand the new exact-operation marker. The matching Harness MCP connector is a separate Host update, not code shipped inside the Identity/PAP/ANP npm packages.
